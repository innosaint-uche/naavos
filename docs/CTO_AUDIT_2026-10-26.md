# NAAvOS end-to-end CTO review

Reviewed 26 October 2026. Baselines: NAAvOS `c515a8417e7430f386e2bf1fd1bdf4e844b55512`; local runtime
`f9666f740eac4224df3f42ee5f20886f0a10bbb3`.

## Verdict

Keep NAAvOS as the main product. Keep the companion repository as its desktop and local runtime layer. The existing
boundaries are sufficient for the current development release; replacing the stack or merging repositories would not fix
the failures found in this review.

The changes provide a working local source journey: offline setup, identity/preferences/rules editing, SQLite
persistence, compiler-compatible export, MCP context retrieval, explicit memory approval, search, deletion and
backup/restore. The hosted service still requires a properly configured resource-bound OAuth authority and live
acceptance evidence before customer release.

## Observed public state

- `https://naavos.radoss.agency/` loads and links the existing unsigned desktop beta.
- The public site is a landing/distribution page. It is not an authenticated hosted Avatar editor.
- The deployed gateway `/health` reports `huggingface-oauth`, D1 configured and release marker
  `e79819d414731cda4d6cc25726842c94621e059c37ee523191bd5e7b68ec84aa`.
- The dashboard-advertised `/.well-known/oauth-protected-resource/mcp` route returns `{"error":"not_found"}` on that
  deployment.
- The existing beta release assets are published. Their presence does not prove installation, signing or compatibility
  with these new source changes.
- Historical September QA/deployment records remain historical. Their central evidence files are absent from this
  workspace.

## Changed

| Boundary                   | Finding                                                                                                                             | Repair                                                                                                             |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Hosted authentication      | Reads did not require the read scope; development authentication could bypass bearer auth on public origins                         | Enforce read/write scopes, reject invalid credentials and restrict anonymous development mode to loopback          |
| Token validation           | Invalid expiry/subject/signature types could bypass normal validation or cause errors                                               | Validate finite temporal claims, issuer, audience, subject and signature; malformed tokens fail closed             |
| Provider boundary          | A Hugging Face identity lookup was treated as proof of a NAAvOS resource token                                                      | Remove that acceptance path; accept dedicated audience-checked JWTs or active audience-checked OAuth introspection |
| OAuth discovery            | Challenge pointed to authorization metadata; advertised resource metadata path was missing                                          | Implement root/path resource discovery, preserve resource/issuer distinction and return scope challenges           |
| MCP input/session handling | Unbounded body buffering, weak argument checks and notifications without sessions                                                   | Bound streaming input, enforce argument shapes, check sessions before notifications, hide internal errors          |
| Hosted data lifecycle      | No owner-scoped data deletion tool                                                                                                  | Add confirmation/scope-gated transactional Avatar, memory and session deletion; preserve other tenants             |
| Local product              | Setup named an Avatar but provided no personality/rules editor                                                                      | Add local editor, SQLite profile, shared-schema export and `avatar_get`                                            |
| Local memory               | Approval/search internals lacked a complete user journey                                                                            | Add explicit save/search/delete UI and MCP tools; pause blocks private context; explain backup retention           |
| Local HTTP boundary        | Origin checking did not defend against hostile Host headers or non-JSON mutation requests                                           | Validate Host, Origin and body shapes, bound UTF-8 input and serialize local actions                               |
| Compiler fidelity          | Some adapters replaced or omitted preferences, scopes, exceptions, modes and references                                             | Use one shared context renderer; deterministic output; references remain references                                |
| Compilation safety         | Mode IDs could become traversal paths and prototype-property names could resolve as adapters                                        | Validate mode filenames and use own-property adapter lookup                                                        |
| ReMe privacy               | Automatic memory/dream capture defaulted on; config values could corrupt YAML                                                       | Default capture off, require explicit consent, validate service port and workspace path                            |
| Installation               | ReMe dry runs could write; destination symlinks could redirect writes                                                               | Remove dry-run mutations, preflight paths and refuse symlink destinations                                          |
| Export/rollback            | Exports could include stale cached context; backups had collision/privacy weaknesses                                                | Recompile current source, use unique private backups and validate restore destinations                             |
| Evaluation                 | Failed checks and missing Avatar health could exit successfully                                                                     | Nonzero failure exits, actual fallback packs and explicit static-conformance language                              |
| Dependencies/build         | Production audit reported 3 critical, 13 high, 13 moderate and 2 low advisory findings; builds required Google Fonts network access | Update Next.js/React/Zod and vulnerable transitive packages, remove unused dependencies and self-host font assets  |
| Distribution               | SEA detection and cross-target guard were unreliable                                                                                | Use the Node SEA API, reject cross-target binaries and test the actual packaged sidecar                            |
| Release evidence           | Historical metadata validation printed a generic pass                                                                               | Separate manifest validity from source-bound production certification; add `verify:release`                        |
| Public claims              | Static counts and behavioural guarantees exceeded available evidence                                                                | Remove unsupported guarantees and retain explicit adapter/host acceptance labels                                   |

## Validation

Run the repeatable checks from this repository:

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm build
corepack pnpm test
corepack pnpm lint
corepack pnpm typecheck
corepack pnpm format:check
corepack pnpm verify:cli
node scripts/verify-cli-doctor.mjs
corepack pnpm verify:claims
corepack pnpm audit --prod
corepack pnpm verify:evidence
```

`verify:evidence` validates the recorded manifest and explicitly does not certify production. `verify:release` must fail
until current source, central artifacts, two live-user isolation, named-host acceptance and signed distribution evidence
are supplied.

The runtime repository includes isolated unit/API/SQLite/MCP tests, a browser journey and a packaged-sidecar
verification script. The runtime's new profile export was checked against the main repository's actual schema/compiler.
Browser CI evidence is separate from API-only checks. This workspace's cloud browser cannot reach its local loopback
server.

The updated production dependency audit reports zero advisories. This is an observed audit result, not a guarantee
against unknown vulnerabilities. Next.js security patch selection was checked against the maintainer's
[14 October 2026 notice](https://nextjs.org/blog/nextjs-security-update-october-14-2026). Zod `4.6.7` was checked
against its [maintainer release](https://github.com/colinhacks/zod/releases/tag/v4.6.7).

## Not validated

- Deployment of this source to Coolify or the Worker. Repository access does not provide those deployment credentials.
- A real OAuth issuer/client flow issuing NAAvOS-audience tokens. Identity-provider account tokens are no longer a
  supported shortcut.
- Migration of existing `hf:<username>` hosted tenant identities to a new issuer's subjects. Preserve the D1 database
  and use a verified owner mapping; do not infer it.
- Two independent live users, token refresh/revocation, or named ChatGPT/Claude acceptance on the changed gateway.
- Production desktop signing, notarisation, native installation and real host reloads across macOS/Windows/Linux.
- A workload/capacity model or commercial hosted-service operations. No capacity target was supplied or inferred.

## Risks and next action

Apply [the corrected gateway deployment procedure](CLOUDFLARE.md) in an isolated environment first. Configure a
dedicated OAuth authority and verified tenant mapping before replacing the existing live gateway. Keep customer release
blocked until the actual production gate passes. Rebuild desktop artifacts from reviewed source; the current
downloadable beta predates these changes.
