# NAAvOS — Development Guidelines

## Code Quality Standards

### Module System
- All packages use **ESM exclusively** (`"type": "module"`, `import`/`export`). Never use `require()` or `module.exports`.
- Use `import.meta.url` + `fileURLToPath` to resolve `__dirname` in ESM:
  ```js
  import { fileURLToPath } from 'url';
  const __dirname = path.dirname(fileURLToPath(import.meta.url));
  ```

### File Header Comments
- Every non-trivial module opens with a JSDoc block comment stating purpose:
  ```js
  /**
   * NAAvOS MCP Server — Cloudflare Workers
   * Model Context Protocol endpoint for AI tool integration
   */
  ```

### Naming Conventions
- **snake_case** for all JSON/schema field names (`package_id`, `owner_id`, `host_id`, `operating_rules`)
- **camelCase** for JavaScript variables and function names (`loadAvatar`, `createBackup`, `runEval`)
- **PascalCase** for Zod schemas and TypeScript types (`AvatarPackageSchema`, `RuleSchema`, `MetadataSchema`)
- **kebab-case** for target/host IDs (`claude-code`, `eval-pack-core-v1`)
- **SCREAMING_SNAKE_CASE** for constants (`ADAPTERS`, `PACKS_DIR`)

### Function Design
- Keep functions small and single-purpose (e.g., `generateSoul`, `generateSkill`, `generateMemory` are separate)
- Helper functions are module-private (not exported); only the public API is exported
- Async functions use `async/await` consistently — no raw Promise chains

## Schema Patterns (Zod)

### Schema-First Validation
Always validate with `AvatarPackageSchema.parse(data)` before any compilation or installation. Never skip validation.

```js
import { AvatarPackageSchema } from '@naavos/schema';
const parsed = AvatarPackageSchema.parse(avatarData); // throws ZodError on failure
```

### Schema Definition Style
- Every field has a `.describe()` annotation explaining its purpose
- Optional fields use `.optional()` explicitly
- Enums use `z.enum([...])` with explicit string literals
- Defaults are set with `.default(value)` on the schema, not in application code
- Regex validation for structured strings (semver, ISO dates, UUIDs):
  ```js
  z.string().regex(/^\d+\.\d+\.\d+$/).describe("Semantic version")
  z.string().uuid().describe("Unique ID")
  z.string().datetime().describe("ISO 8601 timestamp")
  ```

### Discriminated Union Pattern (Knowledge Sources)
Use `z.literal()` + `.extend()` for typed connector schemas, then `z.union([...])`:
```js
const CogneeSchema = BaseSchema.extend({ type: z.literal('connector-cognee'), config: z.object({...}) });
const FilesystemSchema = BaseSchema.extend({ type: z.literal('connector-filesystem'), config: z.object({...}) });
export const KnowledgeSourceSchema = z.union([CogneeSchema, FilesystemSchema, ...]);
```

### TypeScript Type Inference
Derive types from schemas using `z.infer<>`:
```ts
export type AvatarPackage = z.infer<typeof AvatarPackageSchema>;
```

## Compiler / Adapter Patterns

### Adapter Contract
Every adapter receives the validated `AvatarPackageSchema` object and returns `Map<string, string>` (filePath → content):
```js
export function myAdapter(pkg) {
  const files = new Map();
  files.set('OUTPUT.md', generateContent(pkg));
  return files;
}
```

### Defensive Destructuring
Always use fallback defaults when accessing pkg fields in adapters:
```js
const identity = pkg.identity || {};
const rules = pkg.operating_rules || [];
const communication = pkg.communication || {};
```

### Generated File Headers
All compiler-generated markdown files include a "do not edit" notice:
```
> Generated by NAAvOS. Do not edit manually — recompile instead.
```

### Adapter Registration
New adapters are registered in the `ADAPTERS` map in `packages/compiler/src/index.js`:
```js
const ADAPTERS = {
  hermes: hermesAdapter,
  'claude-code': claudeCodeAdapter,
  // add new adapters here
};
```

## CLI Patterns

### Command Structure (Commander.js)
Each command follows this pattern:
```js
program
  .command('command-name')
  .description('Short description')
  .option('--flag <value>', 'Description')
  .action(async (options) => {
    const spinner = ora('Loading...').start();
    try {
      // work
      spinner.succeed(chalk.green('Done.'));
    } catch (error) {
      spinner.fail(chalk.red('Failed: ' + error.message));
      process.exit(1);
    }
  });
```

### Error Handling
- All CLI commands wrap logic in `try/catch`
- Failures call `spinner.fail(chalk.red(...))` then `process.exit(1)`
- Validation errors display field-level messages: `error.errors?.map(e => \`${e.path.join('.')}: ${e.message}\`)`

### Avatar File Conventions
- Avatar stored at: `~/.naavos/avatar.json`
- Compiled output at: `~/.naavos/compiled/<target>/`
- Backups at: `~/.naavos/backups/<timestamp>-<target>/`
- Backup journal at: `~/.naavos/backups/journal.json`

### Backup Before Install
Always create a backup before writing to the target host directory:
```js
const backupId = await createBackup(target, data);
```

## Eval Pack Patterns

### Scenario Types
Supported scenario types in eval packs:
- `schema_valid` — validates avatar parses against Zod schema
- `adapter_compiles` — verifies all adapters compile without error
- `rule_present` — checks a specific rule ID exists in `operating_rules`
- `forbidden_pattern_absent` — regex check on compiled output
- `privacy_consent_set` — verifies a specific consent key/value
- `uuid_fields_present` — validates UUID format on metadata fields

### Result Shape
```js
{ packId, packName, total, passed, failed, score, results: [{ id, type, pass, evidence }] }
```

### Evidence Strings
Every scenario result includes a human-readable `evidence` string explaining pass/fail.

## Dashboard (Next.js) Patterns

### Animation
- GSAP + ScrollTrigger for scroll-based animations; always clean up with `ScrollTrigger.getAll().forEach(t => t.kill())` in `useEffect` cleanup
- `framer-motion` available but GSAP is the primary animation library

### Styling
- Tailwind CSS utility classes only — no custom CSS files except `globals.css`
- Dark theme: `bg-[#09090b]` base, `zinc-*` scale for grays, `violet/purple` for brand accents
- Gradient text: `bg-gradient-to-r from-violet-400 to-purple-400 bg-clip-text text-transparent`
- Responsive: mobile-first with `sm:`, `md:`, `lg:` breakpoints

### Fonts
- Body: `Inter` via `next/font/google`, CSS variable `--font-inter`
- Monospace: `JetBrains Mono`, CSS variable `--font-jetbrains-mono`

### Component Data
Static data arrays (platforms, features, steps) are defined at module level as `const`, not inside components.

### SEO
Full metadata in `layout.tsx`: OpenGraph, Twitter card, JSON-LD structured data, canonical URL, robots config.

## MCP Server Patterns (Cloudflare Workers)

### Handler Structure
Route dispatch in the main `fetch` handler; each route delegates to a named `handle*` function:
```js
if (url.pathname === '/mcp/v1/load') return handleLoad(request, env, corsHeaders);
```

### CORS
All responses include CORS headers; OPTIONS preflight returns early with `null` body.

### Response Pattern
All responses use `new Response(JSON.stringify(data), { headers: { ...corsHeaders, 'Content-Type': 'application/json' } })`.

### Error Responses
Catch blocks return `{ error: error.message }` with `status: 400`.

## General Conventions

### Secrets
- Secrets are **never embedded** in avatar packages — only `credentialRef` strings pointing to a secret manager (e.g., `doppler://project/config/KEY`)
- Privacy consents default to `false` (opt-in model)

### Formatting
- Prettier configured for `**/*.{ts,tsx,md,json}` — run `pnpm format` before committing
- No linter configured in most packages yet (`"lint": "echo 'Lint not configured'"`)

### Testing
- Package tests use `node test.js` (plain Node, no test framework)
- CLI syntax check: `node --check bin/naavos.js && node --check index.js`
- Conformance testing via `naavos test` (eval packs), not unit tests

### Adding a New Compile Target
1. Create `packages/compiler/src/adapters/<target>.js` exporting `<target>Adapter(pkg) → Map`
2. Register in `ADAPTERS` map in `packages/compiler/src/index.js`
3. Add install logic in `packages/cli/index.js` `install` command
4. Document in README.md supported targets table
